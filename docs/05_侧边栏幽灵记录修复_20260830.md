# 侧边栏幽灵记录修复原理

## 1. 幽灵条目的成因剖析

在 Codex 桌面客户端中，侧边栏（会话历史目录）的数据来源并非直接实时扫描 `.codex/sessions` 物理目录，而是首先读取本地 UI 目录数据库：

`%USERPROFILE%\.codex\sqlite\codex-dev.db` 中的 `local_thread_catalog` 表。

当开发者手动删除物理 rollout 文件后：
- `codex-dev.db` 依然存有 `display_title` 和 `thread_id`；
- `.codex-global-state.json` 依然保留有 `client_ids` 引用；
- 导致侧边栏依然渲染出历史任务标题，点击即引发“找不到文件”异常。

## 2. 专项修复方案

针对幽灵记录，本工具提供**一键精准清理机制（控制台菜单 4）**：
1. 自动比对 `codex-dev.db`、`state_5.sqlite`、`thread_history_1.sqlite` 与物理 rollout 文件；
2. 只有当**物理文件不存在、底层状态与历史均已清空、但侧边栏目录仍有残留**时，才发放 `VERIFIED_GHOST` 标签；
3. 执行前建立快照冷备份，并在事务中精准清理 `local_thread_catalog`、`thread_timeline_ledger` 等目录缓存；
4. 绝不跨范围误删其他正在进行的健康会话。
