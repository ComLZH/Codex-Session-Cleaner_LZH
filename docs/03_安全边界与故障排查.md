# 安全边界与故障排查

## 1. 核心安全防护机制

- **读写分离**：启动、浏览与健康诊断默认只读，不影响正常工作。
- **删除级进程守门**：执行删除前，调用 Windows API 严格枚举 `codex.exe`、`ChatGPT.exe` 及辅助进程，发现未退出立即阻止。
- **排他文件句柄检测**：通过 `kernel32!CreateFileW` 尝试独占打开，防止并发竞态。
- **单实例互斥保护**：内置 Windows 命名互斥锁，严禁两个清理工具实例并发写入。
- **一致性快照冷备份**：基于 Python 原生 `Connection.backup()` 逐库备份至 `%LOCALAPPDATA%\CodexCleanup\backups\` 并生成 SHA-256 清单。
- **同卷原子隔离区**：物理文件（rollout、locks）先原子移入同物理卷隔离区，不直接物理碎纸化销毁。
- **动态确认短语**：必须逐字输入带操作码的安全短语（如 `确认删除3个本机会话 A7C19E2B`）。
- **分库拓扑事务与后置校验**：严格遵守外键时序，删除后自动执行 `foreign_key_check` 与 `quick_check`。

## 2. 常见退出代码与排查

- `0`：程序正常完成或安全退出。
- `1`：程序异常，例如数据库损坏、权限不足或缺少 Python 环境。
- `3`：Codex 仍在运行，删除操作被安全阻止。
- `4`：人工确认短语不匹配，删除操作安全取消。
- `130`：用户按 `Ctrl+C` 中止。

## 3. “检测到 Codex 正在运行”的处置方法

说明 Codex 桌面程序或其后台托盘进程尚未完全退出。处置建议：

1. 关闭 Codex 主窗口；
2. 展开 Windows 右下角系统托盘，右键点击 Codex 图标选择“退出”或“Quit”；
3. 重新打开清理工具，即可正常通过安全守门。

不要尝试强行删除锁文件来绕过检查，以免在数据库正在写入时造成损坏。

## 4. 数据库被锁定或无法打开

1. 保持 Codex 关闭后重试；
2. 若持续报告被锁定，检查是否有杀毒软件、网盘同步软件或第三方备份工具正在扫描 `.codex` 目录；
3. 工具内置 `PRAGMA busy_timeout = 5000` 提供 5 秒有界等待缓冲。

## 5. 云端与本地边界声明

官方 OpenAI 文档当前只公开了归档和恢复接口，没有公开 Codex 桌面任务的云端物理删除接口。因此，本工具保证彻底清理本机 SQLite、JSON 索引和磁盘缓存，但无法证明 OpenAI 云端服务器或跨设备同步端是否物理删除了对应数据副本。
