# 旧自动方案复盘

## 1. 历史演进背景

早期方案曾尝试启动后台隐藏 Python 进程，等待 Codex 释放任务锁后自动清理。实际推演发现：

- 后台进程静默退出后，使用者无法及时获知状态；
- 数据删除缺少明确的交互确认时点；
- 依赖用户在看到最终消息后完全退出 Codex，无法在同一会话中闭环验收；
- 自动等待与物理写入组合在一起，降低了用户对执行时点的掌控力。

## 2. 交互理念重构

经过反思与复盘，本工具摒弃了一切“后台静默驻留”、“自动异步等待”的黑盒设计，转为完全由使用者主动掌控的交互模式：

1. **显式控制台主界面**：程序在前台以清爽的控制台窗口运行，所有操作均有明确输出与回显；
2. **读写分离与有界轮询**：平时作为只读审计工具随时可用；删除时显式要求正常退出并进行有界守门；
3. **确认短语防误触**：必须通过 Dry-run 预审并输入带操作码的短语后方可触发物理写入；
4. **状态透明与可追溯**：每次操作均生成结构化 JSON 报告与冷备份清单。
