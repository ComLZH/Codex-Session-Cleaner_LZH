## 📖 为什么做这个工具？

这个项目起于我使用 Codex 时一个很直接的需求：**我想手动删除一部分不再需要的对话，管理自己电脑上保存的会话记录。**

随着使用时间增加，不同项目里积累了越来越多的对话。有些值得保留，有些只是临时提问、重复尝试，或者已经结束的工作。我希望能够自己选择哪些留下、哪些删除。

在我开始开发这个工具时，Codex 客户端提供的归档方式并不能满足这一需求：对话归档后，相关记录仍然保留在本地电脑上，我没有找到能直接完成这些本地记录清理的操作入口。

这也是本项目想为有同样需求的使用者提供的能力：**查看本地会话，明确选择清理对象，并在核对后主动执行删除。**

实际处理过程中，还遇到了关联记录的问题：只删除会话正文文件，数据库和索引里可能仍然保留标题，导致侧边栏出现点不开的“幽灵记录”。因此，工具也加入了关联记录清理与幽灵条目处理功能。

> **这里的“删除”指什么？** 工具清理选中会话在受支持本地数据库和索引中的记录，并将对应会话文件移入隔离区。备份和隔离文件仍保留在电脑上；这不等于安全擦除，也不代表服务端或其他设备上的副本被删除。

## ✨ 可以用它做什么？

| 需求 | 对应功能 |
| :--- | :--- |
| 查看不同项目积累了哪些对话 | 扫描当前用户默认 `.codex` 数据根中的可识别会话，按工作目录分组展示 |
| 手动删除一条或多条不再需要的对话 | 输入会话编号、编号列表或区间，例如 `1`、`1,3`、`2-5` |
| 清理某个明确的会话 | 输入完整 Thread ID，定位当前扫描列表中的目标 |
| 核对自己选中的对象 | 查看标题、工作目录、记录来源、正文文件路径和状态；删除前显示计划并要求确认短语 |
| 处理正文已删、标题仍在的残留 | 批量选择被扫描器识别为“幽灵残留”的本地条目，确认后清理 |
| 排查本地存储问题 | 查看会话证据摘要，执行 SQLite 只读健康检查 |

操作以**整条会话**为单位，不支持删除一条对话里的某几条消息。项目分组用于浏览和选择，不代表删除项目源码或一键清除项目的全部数据。

## 🖥️ 快速上手

### 1. 下载并启动

下载仓库 ZIP 并解压，或克隆仓库。在项目根目录双击：

**`启动Codex清理工具.cmd`**

源码运行需要 **Windows 和 Python 3.10+**，无需安装第三方 Python 包。启动器优先尝试使用当前用户 Codex 缓存目录中的 Python，再尝试其他已配置的解释器；如果没有可用环境，需要自行安装 Python 并加入 PATH。

启动后会显示扫描概况和操作菜单。输入 `2` 查看按项目分组的会话清单；Codex 运行期间也可以进行只读浏览。

### 2. 选择要删除的对话

1. 查看会话清单，确定要删除的标题和所属工作目录；需要更多信息时，输入 `3` 查看证据摘要。
2. 保存正在进行的工作，完全退出 Codex，包括仍在运行的托盘或后台进程。
3. 在工具中输入 `1` 重新扫描，再输入 `5` 查看清单并选择会话。
4. 输入当前清单中的编号，例如 `1,3` 或 `2-5`。支持全角数字、中文逗号等常见输入形式。
5. 核对 Dry-run 预审中列出的目标会话、预计影响范围和备份位置。
6. 按提示输入包含操作码的确认短语，例如 `确认删除2个本机会话 A7C19E2B`。以本次屏幕显示为准；直接回车可取消。
7. 完成后查看备份位置与审计报告，重新打开 Codex，核对目标会话和需要保留的会话。

例如，某项目下有三条对话，当前编号分别是 `1`（正式开发）、`2`（临时测试）、`3`（重复尝试）。如果只想清理后两条，在菜单 `5` 中输入 `2,3`，再核对预审中的标题和 Thread ID。

### 3. 其他操作入口

以下为菜单功能摘要，编号与当前程序一致：

| 编号 | 功能 |
| :---: | :--- |
| `1` | 重新扫描当前数据根 |
| `2` | 查看按项目分组的会话清单 |
| `3` | 查看指定会话的证据摘要 |
| `4` | 选择所有被识别为“幽灵残留”的条目，进入清理预审与确认 |
| `5` | 按编号选择单条或多条会话删除 |
| `6` | 按完整 Thread ID 定向选择会话删除 |
| `7` | SQLite 只读健康检查 |
| `8` | 可选 SQLite 空间维护（VACUUM） |
| `0` | 退出 |

当前控制台界面和删除确认短语使用中文。英文 README 提供对应操作说明。

## 🔍 为什么还要清理数据库和索引？

在本项目调查的本地存储结构中，一条会话可能关联多处数据。只移除 `rollout-*.jsonl` 正文文件，其他位置的记录可能仍然存在。

| 存储位置（相对于 `.codex`） | 相关内容 |
| :--- | :--- |
| `sessions/` 下的 rollout 文件 | 会话正文记录；执行时使用状态库提供的文件路径 |
| `sqlite/codex-dev.db` | 侧边栏目录、标题及其他会话关联记录 |
| `state_5.sqlite`、`sqlite/state_5.sqlite` | 会话状态、标题和正文路径 |
| `thread_history_1.sqlite` | 会话轮次、消息条目及历史投影 |
| `logs_2.sqlite`、`sqlite/logs_2.sqlite` | 按 Thread ID 关联的日志 |
| `session_index.jsonl`、`.codex-global-state.json` | 会话索引及当前实现处理的 `client_ids` 映射 |

工具按选中的 Thread ID 清理已实现适配的关联记录。**幽灵残留清理是这套本地会话管理流程中的一个专项功能**；正常、仍可打开的本地会话也可以手动选择删除。

具体存储结构可能随 Codex 版本变化，这些路径和处理规则不代表对所有版本、所有残留位置的完整覆盖。

## 🛡️ 确认、备份与使用边界

当前实现包含删除前进程检查、部分数据库的占用与 WAL 检查、工具写入互斥锁，以及带操作码的确认短语。执行器会建立 SQLite 备份、生成 SHA-256 清单，按数据库分别提交清理事务，并执行外键与完整性检查。

使用前请了解以下具体边界：

- **本机范围**：默认读取当前 Windows 用户的 `%USERPROFILE%\.codex`。识别为非本地来源的会话只读展示，所选目标包含此类会话时会阻止删除；工具不执行服务端或跨设备删除。
- **清理对象**：目标是会话记录及关联数据，项目源码不属于预期清理对象。执行器依赖数据库提供的 rollout 路径，当前实现尚未完成规划中的完整路径边界防护。
- **备份与隔离**：数据库和文本备份保存到 `%LOCALAPPDATA%\CodexCleanup\backups\<operation_id>\`；会话文件移入源卷根目录下的 `.codex_quarantine_<operation_id>`。完成后的报告写入工具目录下的 `reports/`，包含实际路径。备份可能包含未选中会话的数据，隔离文件仍包含正文。
- **恢复能力**：当前版本没有一键恢复入口或跨数据库自动回滚。部分步骤失败时，可能需要根据备份和隔离文件人工恢复；多个数据库与文件操作不构成一次整体原子事务。
- **兼容与验证**：结构诊断不等于完整的写入兼容性门禁；当前测试尚未覆盖完整删除、异常恢复及所有 Codex 版本。本工具不承诺清除对话的所有痕迹。
