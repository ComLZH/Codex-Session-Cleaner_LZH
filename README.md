## 📖 背景痛点：为什么手动删除了会话文件，Codex 侧边栏依然残留？

很多开发者在尝试清理本地 Codex 项目会话时，经常直接去 `.codex/sessions/` 目录下手动删除对应的 `rollout-*.jsonl` 会话文件。

然而，重启 Codex 桌面客户端后，**左侧边栏依然会显示历史会话标题**，点击时则报错提示“文件不存在”（即所谓的**侧边栏幽灵记录**）。

### 根本原因：
Codex 的本地存储并非单文件，而是由多源协同维护的复杂架构：
1. **桌面 UI 目录库** (`.codex/sqlite/codex-dev.db`)：维护 `local_thread_catalog` 等表，侧边栏直接读取此处的元数据缓存；
2. **核心状态引擎** (`.codex/state_5.sqlite`)：维护任务元数据与 `project_id` / `cwd` 外键映射；
3. **历史轮次与投影** (`.codex/thread_history_1.sqlite`)：维护交互明细与 Projection 状态；
4. **全局文本索引** (`.codex/session_index.jsonl`) 与状态 (`.codex-global-state.json`)。

**仅删除物理文件，无法清除各个 SQLite 数据库中的索引残留。** 本工具正是为了彻底、安全地解决此问题而生。

## ✨ 核心特性

* **🚀 零配置开箱即用**：
  * **无需手动安装 Python**：启动器会自动探测并借用 Codex 自身内置的 Python 3 运行时（`%USERPROFILE%\.cache\codex-runtimes\...`），普通用户直接双击即可运行。
  * **零第三方依赖**：底层引擎 100% 基于 Python 标准库开发。
* **🔍 全机多项目自动发现与证据分类**：
  * 自动扫描当前用户下的所有本地项目与全部会话；
  * 基于多源证据模型将每个会话标记为：
    * `[正常完整]`：数据库元数据与物理文件均健康可读；
    * `【幽灵残留】`：仅侧边栏目录残留（正文已不存在，点击报错）；
    * `【正文缺失】`：数据库保留记录但底层物理文件丢失；
    * `[云端同步]`：通过 ChatGPT 账号在云端同步的对话（自动只读保护，严禁误碰）；
    * `[IN_USE]`：当前正被 Codex 进程或写入锁占用。
* **🛡️ 工业级防灾安全防线**：
  * **读写分离与默认只读**：Codex 运行时可随意打开浏览所有会话清单与诊断；只有在正式执行删除时才激活独占守门。
  * **删除级进程守门**：执行删除前必须完全退出 Codex，严密排查后台托盘进程与操作系统排他句柄锁。
  * **一致性快照冷备份**：基于 Python 原生 `sqlite3.Connection.backup()` 逐库建立快照并生成 SHA-256 清单，备份安全保存至 `%LOCALAPPDATA%\CodexCleanup\backups\`。
  * **同物理卷原子隔离区 (Quarantine)**：物理文件先原子移入同卷隔离区，绝不直接物理碎纸化销毁。
  * **动态确认短语拦截**：正式删除前必须输入带随机短操作码的防误触确认短语（如 `确认删除3个本机会话 A7C19E2B`）。
  * **分库拓扑级联事务**：严格遵守外键时序，删除后自动执行 `PRAGMA foreign_key_check` 与 `quick_check`。

### 常用操作指南：
1. **日常查看与排查**：输入 `2` 查看所有会话树；输入 `3` 并输入编号查看某个会话的所有底层数据库行与文件路径。
2. **快速移除幽灵记录**：完全退出 Codex 桌面客户端（确保系统托盘退出），重新打开工具输入 `4`，一键识别并彻底抹除所有侧边栏点击报错的失效标题。
3. **自由多选删除**：输入 `5`，输入要删除的序号列表（支持半角/全角中文逗号，如 `1,3,4`，或区间 `2-5`），通过 Dry-run 预审后输入短语即可精确删除。

## ⚠️ 免责声明与安全边界

1. **绝对安全边界**：本工具只操作本机当前的 `.codex` 数据目录，**绝对不会进入您的任何项目代码目录删除或修改任何源代码文件**。
2. **仅限本机清理**：由于 OpenAI 目前未公开桌面端的永久删除接口，本工具仅处理本机 SQLite、JSON 索引和磁盘存储；本工具无法证明 OpenAI 服务端或跨设备同步端是否物理删除了对应数据。
3. **备份说明**：每次执行清理前，工具均会自动在 `%LOCALAPPDATA%\CodexCleanup\backups\` 生成完整数据库快照，如需恢复可随时调用。
